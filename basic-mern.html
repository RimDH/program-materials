MERN Stack BASICS Guide

Build full apps with login, roles, dashboard & image upload.

1. Welcome to MERN

MERN is the easiest way to build full websites and apps using only JavaScript.

  • One language for everything
  • Very popular in 2026
  • Perfect for beginners

2. What is MERN?

  • MongoDB → save data
  • Express → make backend APIs
  • React → build nice pages
  • Node.js → run JavaScript on server
You write JavaScript for frontend and backend — learn once, use everywhere.

3. How MERN Works (Simple Flow)

User opens browser → sees React page
→ clicks "Login"
→ React sends email/password to backend
→ Express checks → sends token back
→ React saves token → shows dashboard

7. Create User Model

A "model" tells MongoDB what your data looks like — like a blueprint for users.

Why do we need it?

  • Decide what fields a user has (name, email, password)
  • Make sure required fields are filled
  • Auto-add createdAt / updatedAt times

Example: src/models/user.model.js

const mongoose = require("mongoose");

const userSchema = new mongoose.Schema({
  name: {
    type: String,
    required: true,
    trim: true
  },
  email: {
    type: String,
    required: true,
    unique: true,
    lowercase: true
  },
  password: {
    type: String,
    required: true
  },
  role: {
    type: String,
    enum: ["user", "admin"],
    default: "user"
  }
}, { timestamps: true });

module.exports = mongoose.model("User", userSchema);

Visual: User Data Example

{ name: "Alice", email: "alice@example.com", role: "user" }
Tip: The "role" field will help us later show different things to normal users and admins.
Takeaway: Models = rules for your data. Keep them simple at first — add more fields later!

8. What is Middleware?

Middleware is code that runs **between** the request coming in and your final controller function.

Simple analogy

Browser sends request
→
Middleware checks things
→
If OK → controller runs
→
If NOT OK → send error

Common beginner middlewares

  • express.json() → reads JSON body from forms
  • cors → allows React (different port) to talk to backend
  • auth middleware → checks if user has valid JWT token
  • error middleware → catches mistakes and shows nice message
// Example: simple auth check middleware
const protect = (req, res, next) => {
  const token = req.headers.authorization?.split(" ")[1];

  if (!token) {
    return res.status(401).json({ message: "No token, access denied" });
  }

  // ... check token (we'll do this in next slide)

  next(); // OK → go to controller
};
Tip: Think of middleware as security guards or helpers that run before your main code.
Takeaway: You will use middleware for login checks and reading JSON — very common in every MERN app.

9. JWT Login (Backend)

JWT = JSON Web Token. It's like a digital ID card the backend gives to the user after successful login.

Simple login flow (backend side)

  • User sends email + password to /api/login
  • Backend checks if user exists and password matches
  • If correct → create JWT token
  • Send token back to frontend
  • Frontend saves it and uses it for protected pages

Example: Login route + JWT

 
router.post('/login', async (req, res) => {
  const { email, password } = req.body;

  const user = await User.findOne({ email });
  if (!user) return res.status(400).json({ message: "Invalid credentials" });

  const isMatch = await bcrypt.compare(password, user.password);
  if (!isMatch) return res.status(400).json({ message: "Invalid credentials" });

  // Create token
  const token = jwt.sign(
    { id: user._id, role: user.role },
    "mysecretkey123",  // change this in real app!
    { expiresIn: "1d" }
  );

  res.json({ token, role: user.role });
});

Login Success Flow

Frontend → email + password
→
Backend → check → create token
→
Send { token: "xyz..." }
Warning: Never hardcode secret key ("mysecretkey123") in real apps — put it in .env file!
Takeaway: After login, the frontend gets a token. It will send this token in every future request to prove "I am logged in".

10. Simple CRUD (Products)

CRUD = Create, Read, Update, Delete — the 4 basic things we do with data.

Example: Products in our shop app

  • Create → add new product
  • Read → show all products or one product
  • Update → edit product price or name
  • Delete → remove product

Backend route example (routes/product.routes.js)

router.post('/', protect, createProduct);       // Create
router.get('/', getAllProducts);                        // Read all
router.get('/:id', getProductById);                     // Read one
router.put('/:id', protect, updateProduct);             // Update
router.delete('/:id', protect, deleteProduct);          // Delete

Controller example (createProduct)

exports.createProduct = async (req, res) => {
  try {
    const product = new Product({
      name: req.body.name,
      price: req.body.price,
      description: req.body.description,
      user: req.user.id   // who added it (from JWT)
    });
    await product.save();
    res.status(201).json(product);
  } catch (err) {
    res.status(400).json({ message: err.message });
  }
};
Takeaway: CRUD is the heart of most apps — once you know it for products, you can do it for anything (users, orders, posts...).

11. Upload Images (multer)

Users want to upload product photos — we use a helper called **multer** to handle file uploads.

Steps (very simple)

  • Install multer: `npm install multer`
  • Make a folder to save images: `public/uploads`
  • Tell multer where to save files
  • Add upload route

Example middleware + route

// middleware/upload.js
const multer = require('multer');
const storage = multer.diskStorage({
  destination: (req, file, cb) => cb(null, 'public/uploads/'),
  filename: (req, file, cb) => cb(null, Date.now() + '-' + file.originalname)
});
const upload = multer({ storage });

// In routes/product.routes.js
router.post('/upload', protect, upload.single('image'), (req, res) => {
  if (!req.file) return res.status(400).json({ message: 'No file uploaded' });
  res.json({ imageUrl: `/uploads/${req.file.filename}` });
});

Upload Flow

Frontend → choose photo
→
Send to /api/upload
→
Backend saves file → returns URL
→
Save URL in product
Tip: In real apps save images to cloud (Cloudinary or AWS S3) later — but local folder is perfect for learning.

14. Call APIs in React

React needs to talk to the backend — we use fetch or axios to send requests.

Simple example: Get all products (using fetch)

// src/pages/Products.tsx
import { useState, useEffect } from 'react';

function Products() {
  const [products, setProducts] = useState([]);

  useEffect(() => {
    fetch('http://localhost:5000/api/products')
      .then(res => res.json())
      .then(data => setProducts(data))
      .catch(err => console.log(err));
  }, []);

  return (
    <div>
      <h2>Products</h2>
      {products.map(p => (
        <div key={p._id}>
          {p.name} - ${p.price}
        </div>
      ))}
    </div>
  );
}

Cleaner version: Using axios

import axios from 'axios';

useEffect(() => {
  axios.get('http://localhost:5000/api/products')
    .then(res => setProducts(res.data))
    .catch(err => console.log(err));
}, []);

API Call Flow

React → fetch / axios → backend
→
Backend sends JSON data
→
React updates list on screen
Tip: In real apps, put all API calls in one file like src/services/api.ts so you can reuse them easily.
Takeaway: useEffect + fetch or axios = the basic way React talks to your backend. This pattern is used in almost every app!

15. Login Page in React

Simple form → user types email + password → send to backend → get token back.

Example: Login page (src/pages/Login.tsx)

// src/pages/Login.tsx
import { useState } from 'react';
import axios from 'axios';
import { useNavigate } from 'react-router-dom';

function Login() {
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const navigate = useNavigate();

  const handleSubmit = async (e) => {
    e.preventDefault();
    try {
      const res = await axios.post('http://localhost:5000/api/auth/login', { email, password });
      localStorage.setItem('token', res.data.token);
      localStorage.setItem('role', res.data.role);
      navigate('/dashboard');
    } catch (err) {
      alert('Login failed!');
    }
  };

  return (
    <form onSubmit={handleSubmit}>
      <input 
        type="email" 
        value={email} 
        onChange={e => setEmail(e.target.value)} 
        placeholder="Email" 
        required 
      />
      <input 
        type="password" 
        value={password} 
        onChange={e => setPassword(e.target.value)} 
        placeholder="Password" 
        required 
      />
      <button type="submit">Login</button>
    </form>
  );
}

export default Login;

Login Success Flow

User fills email + password → clicks Login
→
React sends data to backend
→
Backend says OK → token & role saved in localStorage
→
Redirects to dashboard
Tip: We save the token and role in localStorage — this is a simple beginner way to stay logged in even after refresh.
Takeaway: The login page collects data → sends it to backend → saves the token → moves to dashboard. This is the key step that makes the whole app feel secure and personal!

16. Keep Logged In (localStorage)

After login, we don't want the user to have to log in again every time they refresh the page or close the tab.

Simple way: Save token in localStorage

  • localStorage keeps data even after refreshing
  • We save the JWT token and user role after successful login
  • On every page load, check if token exists → show dashboard
  • If no token → show login page

Example: AuthContext with login status check (src/context/AuthContext.tsx)

// src/context/AuthContext.tsx (simple version)
import { createContext, useState, useEffect } from 'react';

export const AuthContext = createContext();

export const AuthProvider = ({ children }) => {
  const [user, setUser] = useState(null);

  useEffect(() => {
    const token = localStorage.getItem('token');
    const role = localStorage.getItem('role');
    if (token) {
      setUser({ token, role });
    }
  }, []);

  const login = (token, role) => {
    localStorage.setItem('token', token);
    localStorage.setItem('role', role);
    setUser({ token, role });
  };

  const logout = () => {
    localStorage.removeItem('token');
    localStorage.removeItem('role');
    setUser(null);
  };

  return (
    <AuthContext.Provider value={{ user, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
};
Tip: Wrap your whole app in inside index.js or main.tsx so every page can access login status:

<AuthProvider>
  <App />
</AuthProvider>
Takeaway: localStorage + React Context = a simple, beginner-friendly way to keep the user logged in across pages, refreshes, and even after closing the tab.
Warning (for later): localStorage is easy but not super secure. In some apps you might use httpOnly cookies for tokens — but for learning, localStorage is perfect.

17. Protected Routes & Dashboard

Some pages (like the dashboard) should only be visible if the user is logged in. We use a special component called ProtectedRoute to protect them.

What ProtectedRoute does

  • Checks if the user is logged in (has a token from context)
  • If yes → shows the page
  • If no → redirects to the login page

ProtectedRoute Component (src/components/ProtectedRoute.tsx)

import { useContext } from 'react';
import { Navigate } from 'react-router-dom';
import { AuthContext } from '../context/AuthContext';

const ProtectedRoute = ({ children }) => {
  const { user } = useContext(AuthContext);

  if (!user) {
    return ;
  }

  return children;
};

export default ProtectedRoute;

Use it in App.tsx routes 

import { BrowserRouter, Routes, Route } from 'react-router-dom';
import ProtectedRoute from './components/ProtectedRoute';
import Dashboard from './pages/Dashboard';
import Login from './pages/Login';

function App() {
  return (
    
      

        // Public route - anyone can visit login page
        <Route path="/login" element={<Login />} />

        // Protected route - only logged-in users can see dashboard
        <Route 
          path="/dashboard" 
          element={
            <ProtectedRoute>
              <Dashboard />
            </ProtectedRoute>
          } 
        />

        // You can protect more pages the same way
        // <Route path="/profile" element={<ProtectedRoute><Profile /></ProtectedRoute>} />

      
    
  );
}

export default App;

Protected Route Flow

User tries /dashboard
→
ProtectedRoute checks: Is user logged in?
→ Yes →
Shows Dashboard
→ No →
Redirects to /login
Tip: The login page is **not** wrapped in ProtectedRoute — that's why everyone can see it. Private pages (dashboard, profile, etc.) are wrapped.
Takeaway: Use around every private page — it's a clean, common way to protect routes in React apps.

18. Role-Based Dashboard (Admin / User)

Different users see different things: Admins see more options (like manage users), normal users see basic dashboard only.

Simple role check

  • Save role ("user" or "admin") during login (from backend)
  • In dashboard, show or hide buttons based on role

Example: Dashboard page (src/pages/Dashboard.tsx)

// src/pages/Dashboard.tsx
import { useContext } from 'react';
import { AuthContext } from '../context/AuthContext';

function Dashboard() {
  const { user, logout } = useContext(AuthContext);

  return (
    <div>
      <h1>
        Welcome, {user.role === 'admin' ? 'Admin' : 'User'}!
      </h1>

      <p>Your dashboard</p>

      {user.role === 'admin' && (
        <button>Manage All Users (Admin Only)</button>
      )}

      <button onClick={logout}>Logout</button>
    </div>
  );
}

export default Dashboard;

Role-Based View

Normal User → sees basic welcome + Logout button
Admin → sees extra "Manage All Users" button
Tip: Use simple checks like {user.role === 'admin' && ...} — it's easy and perfect for beginners. Add more admin features later.
Takeaway: The role comes from the token → React uses conditional rendering to show different things to admins and normal users — super useful for real apps!
Warning: In real apps, never trust the frontend role alone — always double-check permissions on the backend too (for security).

19. Frontend CRUD Example

Now let's connect React to our backend CRUD APIs — show products, add new, edit, delete — all in one page!

Simple Products page with full CRUD

  • Get all products → show list
  • Add new product (form)
  • Edit product (click Edit → form fills → save)
  • Delete product (click Delete)

Example: Products Page (src/pages/Products.tsx)

// src/pages/Products.tsx
import { useState, useEffect } from 'react';
import axios from 'axios';

function Products() {
  const [products, setProducts] = useState([]);
  const [name, setName] = useState('');
  const [price, setPrice] = useState('');
  const [editingId, setEditingId] = useState(null); // which product we are editing

  // Load all products on mount
  useEffect(() => {
    axios.get('http://localhost:5000/api/products')
      .then(res => setProducts(res.data))
      .catch(err => console.log(err));
  }, []);

  // Add OR Update product
  const handleSubmit = async (e) => {
    e.preventDefault();

    const productData = { name, price: Number(price) };

    try {
      if (editingId) {
        // Edit existing
        const res = await axios.put(`http://localhost:5000/api/products/${editingId}`, productData);
        setProducts(products.map(p => p._id === editingId ? res.data : p));
        setEditingId(null);
      } else {
        // Add new
        const res = await axios.post('http://localhost:5000/api/products', productData);
        setProducts([...products, res.data]);
      }

      // Clear form
      setName('');
      setPrice('');
    } catch (err) {
      alert('Error saving product');
    }
  };

  // Start editing a product
  const startEdit = (product) => {
    setName(product.name);
    setPrice(product.price);
    setEditingId(product._id);
  };

  // Delete product
  const deleteProduct = async (id) => {
    if (window.confirm('Delete this product?')) {
      await axios.delete(`http://localhost:5000/api/products/${id}`);
      setProducts(products.filter(p => p._id !== id));
    }
  };

  return (
    <div>
      <h2>Products List</h2>

      <form onSubmit={handleSubmit}>
        <input 
          value={name} 
          onChange={e => setName(e.target.value)} 
          placeholder="Product name" 
          required 
        />
        <input 
          type="number" 
          value={price} 
          onChange={e => setPrice(e.target.value)} 
          placeholder="Price" 
          required 
        />
        <button type="submit">
          {editingId ? 'Update Product' : 'Add Product'}
        </button>
        {editingId && (
          <button type="button" onClick={() => { setEditingId(null); setName(''); setPrice(''); }}>
            Cancel Edit
          </button>
        )}
      </form>

      {products.map(p => (
        <div key={p._id}>
          {p.name} - ${p.price}
          <button onClick={() => startEdit(p)}>Edit</button>
          <button onClick={() => deleteProduct(p._id)}>Delete</button>
        </div>
      ))}
    </div>
  );
}

export default Products;

Full CRUD Flow

List loads → Add new → appears
Click Edit → form fills → Update → list refreshes
Click Delete → gone!
Tip: When editing, we reuse the same form — just change button text and fill inputs. Simple and clean!
Takeaway: With useState + useEffect + axios you can build full CRUD in React — add, edit, delete, all connected to your backend.
