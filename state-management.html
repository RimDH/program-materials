State Management

The Modern React Stack: Zustand & TanStack Query

Stop drilling props. Start architecting high-performance websites.

Why Use State Management?

In medium to large websites, state management is the brain that keeps your UI in sync.

Avoid Prop Drilling

Passing data through 10 layers of components just to reach a button is a nightmare. State management provides a teleportation link directly to the component that needs it.

Performance

Large apps struggle with re-renders. Modern tools ensure only the exact component watching a specific piece of data updates when that data changes.

The Goal: Create a "Single Source of Truth" so your Header, Sidebar, and Profile never show different information.

The State Ecosystem

We divide state based on where it comes from and who needs it.

SERVER STATE (TanStack Query)

Remote data (APIs). Needs caching, re-fetching, and loading indicators.

GLOBAL UI STATE (Zustand)

App-wide settings. Dark mode, sidebar status, multi-step form drafts.

LOCAL STATE (useState)

Component secrets. Is this dropdown open? What is the current input text?

Create & Use a Zustand Store

Zustand allows you to define state once and "teleport" it to any component without prop-drilling.

1. The Store (Definition)

import { create } from 'zustand';

// Define the "Blueprint"
interface UIStore {
  theme: 'light' | 'dark';
  toggle: () => void;
}

// Create the actual "Hook"
export const useUIStore = create<UIStore>((set) => ({
  theme: 'light',
  toggle: () => set((state) => ({ 
    theme: state.theme === 'light' ? 'dark' : 'light' 
  })),
}));

2. The Component (Usage)

import { useUIStore } from './store';

export function ThemeToggle() {
  // Select only the data you need
  const theme = useUIStore((s) => s.theme);
  const toggle = useUIStore((s) => s.toggle);

  return (
    <button onClick={toggle} className={theme}>
      Switch to {theme === 'light' ? 'Dark' : 'Light'}
    </button>
  );
}

Main Parts: The Store

  • create<T>: Initializes the store. In TypeScript, the <T> ensures the store follows your interface rules.
  • set(): The core function that merges new data into the store. It is reactive, meaning it automatically notifies components.

Main Parts: The Component

  • Selectors: (s) => s.theme is a selector. It tells React to only re-render this component if the theme changes, ignoring other store updates.
  • Import & Use: No <Provider> wrapping is required. Just import the hook and start using it.

TanStack Query: The Infrastructure

First, we wrap the application in a Provider. This creates the "Cache Brain" that manages all your API data globally.

src/main.tsx (or index.tsx)

import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

// 1. Create a client instance
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 1000 * 60,     // 1 minute - how long data stays 'fresh'
      gcTime: 1000 * 60 * 5,    // 5 minutes - when unused data is deleted
    },
  },
});

ReactDOM.createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <!-- 2. Wrap your app -->
    <QueryClientProvider client={queryClient}>
      <App />
    </QueryClientProvider>
  </React.StrictMode>
);

Main Parts Explained:

  • QueryClient: The core engine. It stores your API results so that if two components ask for the same data, it only fetches once.
  • staleTime: Prevents unnecessary network requests. If you visit a page twice within a minute, it shows the cached data instantly.
  • gcTime: "Garbage Collection." It cleans up the memory by deleting data that hasn't been used for 5 minutes.

TanStack Query: Fetching Data

Inside the component, we use the useQuery hook. No more manual useEffect or useState for loading/errors.

src/components/UserList.tsx

import { useQuery } from '@tanstack/react-query';

async function fetchUsers() {
  const res = await fetch('https://jsonplaceholder.typicode.com/users');
  if (!res.ok) throw new Error('Network response was not ok');
  return res.json();
}

export default function UserList() {
  const { data, isLoading, error } = useQuery({
    queryKey: ['users'], // Unique ID for caching
    queryFn: fetchUsers, // The fetcher function
  });

  if (isLoading) return <p>Loading users...</p>;
  if (error) return <p>Error: {(error as Error).message}</p>;

  return (
    <ul>
      {data?.map((user: any) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}

Main Parts Explained:

  • queryKey: This is like a filename. TanStack looks in the cache for 'users'. If it's there and "fresh," it returns it instantly.
  • queryFn: A function that must return a Promise. It's the "worker" that goes to the internet to get your data.
  • Status Flags: isLoading and error are updated automatically. You don't have to manage these variables manually anymore!

Result: Blazing fast UI and clean, declarative code.

Conclusion

For high-performance, medium to large websites:

Use Zustand for UI behavior.
Use TanStack Query for Server data.

Result: A cleaner codebase, fewer bugs, and a faster user experience.
