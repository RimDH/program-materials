The "Full-Stack React" Era

What is it? A React Framework for building Full-Stack Web Apps.

The Gap: React alone is only the Frontend. Next.js is the Backend and Frontend in one.

Stable Version: v16.x (2026 Standard)

Built-in Routing | Optimized Rendering | Data Fetching

React vs. Next.js: The Evolution

The Old React Way

  • Manual Routing (React Router)
  • Client-side rendering only
  • External API server needed
  • Manual Performance setup

The Next.js Way

  • Built-in File-system Routing
  • Hybrid Server/Client Architecture
  • Built-in API Handlers (Backend)
  • Auto-optimized images and fonts

     └── components/ <-- Global UI

The "Layout" Principle

Next.js follows a Wrapper Pattern. The layout.tsx runs first. It contains your Navbar/Footer.

The {children} are then displayed inside the layout. This allows the page to change without the Navbar re-rendering!

The New Architecture

Next.js relies on React Server Components. You now choose where your code lives.

Server Components

  • Default in Next.js.
  • Rendered only on the Server.
  • No useState or useEffect.
  • Faster: Sends less JS to the user.

Client Components

  • Must use "use client" at top.
  • Rendered on the Browser.
  • Full React Hooks support.
  • Interactive: Buttons, Forms, Inputs.

The 4 Rendering Types

Next.js is "Hybrid." You can use all four of these methods in a single application.

Static (SSG)

At Build Time

Pre-rendered once. Fastest for users.

// Default behavior
fetch('...');
  • Blogs
  • Docs
Hybrid (ISR)

Background

Static, but updates every X seconds.

revalidate: 60
  • News
  • E-commerce
Dynamic (SSR)

On Request

Fresh data for every single visitor.

cache: 'no-store'
  • Live Feeds
  • Dashboards
Client (CSR)

In Browser

Runs 100% on the user's machine.

"use client"
useEffect(...)
  • Charts
  • Modals

When to use CSR? In Next.js, we don't use CSR for the whole page (bad for SEO). Instead, we use it for interactive components like search bars, maps, or buttons that need useState.

In the Code: Server vs. Client

Server (Default)

// No 'use client' here
export default function Page() {
  console.log("I run on the Server!");
  // Output shows in Terminal
  return <h1>Server Data</h1>;
}

Client

"use client";
import { useState } from 'react';

export default function Counter() {
  console.log("I run in Browser!");
  // Output shows in Inspect Console
  return <button>Click Me</button>;
}

The API Folder: Your Built-in Backend

Next.js allows you to build a full API without leaving your app folder. No separate Node/Express server required.

app/
 ├── api/
 │   └── products/
 │       └── route.ts  <-- The Endpoint
 ├── layout.tsx
 └── page.tsx

How it works:

Any route.ts file inside the api/ folder becomes an HTTP endpoint.

Folder: api/products/route.ts

URL: /api/products

CRUD Made Simple

You handle different HTTP methods by exporting named functions (GET, POST, DELETE, etc.) from one file. 

// app/api/products/route.ts
import { NextResponse } from 'next/server';

// 1. READ (GET)
export async function GET() {
  const data = await db.product.findMany(); // Direct DB access!
  return NextResponse.json(data);
}

// 2. CREATE (POST)
export async function POST(req: Request) {
  const body = await req.json();
  const newProduct = await db.product.create({ data: body });
  return NextResponse.json(newProduct, { status: 201 });
}

Fetching Data

Next.js 16 makes fetching data as easy as writing a standard JavaScript function. No more useEffect boilerplate.

Inside your Page (Server Component):

export default async function Page() {
  // 1. Call your API or Database directly
  const response = await fetch('http://localhost:3000/api/products');
  const products = await response.json();

  return (
    <div>
      <h1>Our Store</h1>
      {products.map(p => <p key={p.id}>{p.name}</p>)}
    </div>
  );
}

Why this is Pro: The data is fetched before the HTML is sent to the user. Fast, SEO-friendly, and secure.

When to choose what?

Choose React (Alone)

  • Small prototypes.
  • Non-SEO critical apps.
  • Client-side only dashboards.

Choose Next.js

  • SEO is required (Google visibility).
  • Large production apps.
  • Full-stack needs (Auth, DB, APIs).
  • Best Performance out of the box.

Next.js is the modern standard for professional web development in 2026.
