The "Folder Way" (Routing)

In Next.js, Folders create the URLs. You don't need a separate router file.

app/
 ├── page.tsx      --> /
 ├── about/
 │   └── page.tsx  --> /about
 └── contact/
     └── page.tsx  --> /contact

The Rule:

Every folder represents a path segment. To make it a real page, it must contain a page.tsx file.

Special File Names

Next.js looks for these exact names to provide automatic features:

page.tsx

The main content of the route. This is what the user sees.

layout.tsx

Shared UI (Navbars/Footers) that doesn't re-render on navigation.

loading.tsx

Shown automatically while your data is fetching. No state needed!

error.tsx

A "Safety Net" that shows a custom UI if your page crashes.

Dynamic Routes [id]

Used when you have thousands of pages with the same layout (like products or blog posts).

// Folder: app/product/[id]/page.tsx
// URL: /product/iphone-15

export default function Page({ params }) {
  return <h1>Product ID: {params.id}</h1>
}

The [id] acts as a wildcard variable in your URL.

Route Groups (group)

Parentheses are for Visual Organization only. They are invisible to the URL.

app/
 ├── (auth)/
 │   ├── login/page.tsx
 │   └── layout.tsx  <-- Sidebar for Login
 └── (main)/
     ├── home/page.tsx
     └── layout.tsx  <-- Sidebar for App

Why use them?

1. Organize code without changing the URL (/login instead of /auth/login).

2. Give different sections of your site completely different layouts.

Project Architecture

A professional setup for a Website + Dashboard + API:

src/
 ├── app/
 │   ├── (marketing)/    <-- Home, About, Pricing
 │   ├── (dashboard)/    <-- Protected User Panel
 │   ├── (auth)/         <-- Login / Register
 │   └── api/            <-- Backend Handlers (JSON)
 ├── components/
 │   ├── ui/             <-- Buttons, Modals
 │   └── layout/         <-- Navbars, Sidebars
 └── lib/                <-- Database, Auth logic
